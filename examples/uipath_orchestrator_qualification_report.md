## 4. Security Requirements

### User and SCC

| Criterion | Documented Value | OpenShift Impact |
|-----------|-----------------|------------------|
| Runtime user | `orchestrator` (UID 1000) | Fixed UID → incompatible with `restricted-v2` (random UID) |
| Root required | Yes, for installation and certificate management | Not needed at runtime if certs are mounted via Secret |
| Capabilities | `CAP_NET_BIND_SERVICE` (bind port 443) | Requires custom SCC or switch to port > 1024 |

**Recommended SCC: `nonroot-v2` with adjustments**
- Mount TLS certificates via Kubernetes **Secret** instead of system keystore → removes root requirement
- Use an internal port > 1024 (e.g., 8443) and let the OpenShift **Route** handle TLS on port 443 → removes `CAP_NET_BIND_SERVICE` requirement
- Set `runAsUser: 1000` in the pod SecurityContext

### TLS Certificates

## 7. Compatibility Alerts

### 🔴 BLOCKER

1. **`CAP_NET_BIND_SERVICE` required for port 443**
   The application attempts to bind directly to port 443. On OpenShift, non-privileged pods cannot use ports < 1024.
   **Workaround:** configure the application on a port > 1024 (e.g., 8443) and use an OpenShift Route to expose on 443. Verify that the `ORCHESTRATOR_PORT` configuration variable is available.

2. **RWX storage required for HA mode**
   The `packages` and `media` volumes must be shared across instances. If the cluster does not have an RWX StorageClass (NFS, CephFS), HA mode is impossible.
   **Action:** verify RWX StorageClass availability with the platform team.

### 🟡 WARNING

3. **Fixed UID (1000) — incompatible with `restricted-v2` default**
   OpenShift's `restricted-v2` SCC assigns random UIDs. The application expects UID 1000.
   **Workaround:** use the `nonroot-v2` SCC and set `runAsUser: 1000` in the Deployment. Requires security team validation.

4. **Logs written to disk, not stdout**
   Logs are written to `/var/log/uipath/` as rotating files. This prevents collection by the OpenShift logging stack (Fluentd/Vector).
   **Workaround:** check if UiPath supports a stdout redirect option, or deploy a log collection sidecar.

5. **System keystore access for TLS certificates**
   The application expects to read certificates from `/etc/ssl/certs/`. On OpenShift, certificates are mounted via Secrets.
   **Workaround:** mount a TLS Secret at the expected path, or configure the certificate path via environment variable.

6. **Sticky sessions required**
   HA mode requires session affinity on the load balancer. On OpenShift, this is configured via a Route annotation.
   **Action:** add `haproxy.router.openshift.io/disable_cookies: "false"` to the Route.

### 🟢 OK

7. **Health check endpoint available** — `GET /api/status` (HTTP 200) → usable as `livenessProbe` and `readinessProbe`
8. **Native Prometheus endpoint** — port 10000 `/metrics` → direct integration with OpenShift monitoring
9. **JSON log format** — compatible with structured parsing if redirected to stdout
